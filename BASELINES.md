# Domovoi Labs — Baselines

**Status:** Initial baseline set  
**Date:** 2026-09-15

The baseline set has three jobs:

1. Show what already fits into a small memory budget.
2. Show what a practical compressed small model can do.
3. Define the long-term capability target.

All final numbers should eventually be generated by **our own evaluation harness** under identical prompts and decoding settings. Vendor/model-card scores are only provisional reference numbers.

## Baseline A — Native-fit reference

### EXAONE 4.0 1.2B

**Role:** Main initial native-fit capability baseline.

Why use it:

- small enough for a genuine 4 GiB-class native deployment
- modern model
- unusually strong reported results for its parameter count
- public benchmark results cover reasoning, coding, instruction following, long context and tool use

Officially reported non-reasoning scores include:

| Benchmark | Reported score |
|---|---:|
| MMLU-Pro | 52.0 |
| GPQA-Diamond | 40.1 |
| LiveCodeBench v6 | 30.1 |
| IFEval | 74.7 |
| RULER | 77.4 |
| LongBench v1 | 36.9 |
| BFCL-v3 | 55.7 |

These numbers are references only. Domovoi should re-run the benchmarks before claiming a direct comparison.

**Repository:** https://github.com/LG-AI-EXAONE/EXAONE-4.0

## Baseline B — Same-family small-model reference

### Qwen3.5-2B

**Role:** Modern small-model reference from the same broader Qwen family as the long-term target.

The official BF16 checkpoint is about 4.55 GB of weights, so it does **not** cleanly qualify for the strict 4 GiB native-fit track with runtime overhead.

That is useful rather than inconvenient: it gives Domovoi a nearby comparison point just above the target memory budget.

Measure:

- full-precision/BF16 capability where hardware permits
- best reproducible <=4 GiB deployment as a separate compressed reference
- quality lost when forcing the model under 4 GiB

**Model:** https://huggingface.co/Qwen/Qwen3.5-2B

---

## Baseline C — Practical 4 GiB compressed reference

### Qwen3.5-4B — constrained deployment

**Role:** Show what a modern 4B model can do when post-training compression is allowed.

The official BF16 model is roughly 9.34 GB, so it does not qualify as native-fit. We will select one fixed, reproducible quantized deployment that stays below the 4 GiB runtime limit.

This baseline is important because Domovoi should eventually beat not only tiny native models, but also the practical approach users take today: quantize a larger model until it fits.

The exact quantization artifact/runtime must be pinned before official results are published.

**Model:** https://huggingface.co/Qwen/Qwen3.5-4B

## Long-term target — Qwen3.8-27B

### Qwen3.8-27B

**Role:** Capability target, not memory baseline.

The official model card describes a 27B text model with a vision encoder and a 262K native context window. The released checkpoint is BF16 and is far outside the 4 GiB target.

Published Qwen3.8-27B text results include:

| Benchmark | Published score |
|---|---:|
| IFBench | 79.5 |
| GPQA Diamond | 89.2 |
| HLE | 30.8 |
| LiveCodeBench v6 | 90.3 |
| Terminal Bench 2.1 | 73.0 |
| SWE-bench Pro | 61.7 |

The first Domovoi target is **text capability only**. Matching Qwen3.8-27B vision/video capability is a separate future research problem.

**Model:** https://huggingface.co/Qwen/Qwen3.8-27B

## Baseline rules

Every official Domovoi comparison must record:

- exact model/checkpoint hash
- runtime
- quantization, if any
- GPU
- driver/CUDA version
- context length
- prompt format
- reasoning mode
- temperature/top-p/top-k
- max output tokens
- peak VRAM allocated
- peak VRAM reserved
- prefill speed
- decode speed

Do not compare a Domovoi score produced with tools, retrieval or extra context against a baseline that did not receive the same resources unless the result is explicitly labelled as a **system-level** comparison.

## Baseline hierarchy

The project should answer these questions in order:

1. **Can Domovoi beat EXAONE 4.0 1.2B under the same memory budget?**
2. **Can it beat a compressed Qwen3.5-4B while remaining native-fit?**
3. **How much of Qwen3.8-27B's capability can it recover inside 4 GiB?**

That gives the project measurable steps instead of treating Qwen3.8-27B parity as the only result that matters.
