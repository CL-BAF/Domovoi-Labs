# Architecture review of domovoi_recurrent_v1

## What the implementation establishes

The implementation exposes a useful controlled variable: the assignment of learned Transformer blocks to executed depth. Cycle and sequence use the same modules with different ordering. The residual stream changes after each application and autograd sums the gradient contributions from each use. The CPU probe confirms these properties against an untied unroll with copied initial block values. Learned absolute positions, dense causal attention, the MLP and output head are inherited from the baseline.

The novelty is the proposed measurement regime and efficiency target. Cycle and sequence were evaluated as parameter-sharing schemes by Takase and Kiyono. The Universal Transformer introduced self-attentive depth recurrence with adaptive computation. Huginn explores variable test-time depth with an architecture and training recipe beyond v1's fixed loop. These results motivate a comparison and do not transfer directly to a small causal model under a measured memory limit. [Takase and Kiyono](https://arxiv.org/abs/2104.06022v4) · [Universal Transformers](https://arxiv.org/abs/1807.03819v3) · [Huginn research implementation](https://github.com/seal-rg/recurrent-pretraining)

Sharing buys more sequential transformations for a fixed block-weight budget. Repeated transformations could support iterative computation and can regularize small models. The same tying restricts distinct depth functions and couples their updates. Pre-LN residual paths help gradient propagation, while correlated repeated updates can amplify or cancel gradients. Smooth one-step gradients do not establish long-run stability. Smaller weight storage can reduce bandwidth pressure when kernels benefit from locality. Unchanged attention work at equal effective depth, repeated launches, full-context attention and per-application KV reads can dominate latency. Each application still stores its own K/V, and the current cache implementation adds allocation and copy overhead.

## Training data and positional migration

Tinyshakespeare is a valid pipeline check. Its single-author, narrow-domain split and approximately 80 corpus-equivalents at default budgets prevent a useful estimate of general language capability. A lighter model can appear favorable simply because it overfits the repeated corpus less. Random overlapping windows also mean a nominal one-pass token count does not guarantee unique examples.

Use a deterministic document subset from FineWeb-Edu with its declared ODC-BY license, or DCLM Baseline 1.0 with its declared CC BY 4.0 license. Pin dataset revision, exact upstream crawl/shard IDs, manifests, document sequence and hashes before preparing anything. Check applicable attribution and original-source terms with the release metadata. Split at document/source level before packing, deduplicate across splits, screen exact and approximate overlaps against reserved eval prompts and answers, retain a separate untouched test split, and record filtering counts. Train the shared tokenizer on the training partition alone. For the first run, use one corpus and a fixed data order with no-replacement packed segments where feasible. Save document boundaries and include EOS consistently. [FineWeb-Edu data card](https://huggingface.co/datasets/HuggingFaceFW/fineweb-edu) · [DCLM Baseline 1.0 data card](https://huggingface.co/datasets/mlfoundations/dclm-baseline-1.0)

At 8K a larger learned table keeps the original positional mechanism but adds 4,915,200 parameters relative to the 512-position config. New rows need training and old checkpoints cannot directly load the larger table. RoPE is the preferred first ablation because it avoids that trainable table. Apply the same positions and rotary settings in both model families, rotate queries and keys before cache storage, and validate explicit offsets across prefill, chunked extend and singleton decode. A relative attention bias such as ALiBi is also plausible and can affect kernel dispatch. Either changes the architecture and requires a new versioned baseline. First establish a 512-token positional ablation, then train matched 8K variants with long-range examples. Evaluate retrieval, NLL by position and length, and generation with room left for the continuation. Configuring an 8192-token window alone gives no evidence of usable context. [RoFormer](https://arxiv.org/abs/2104.09864v5)

## Smallest falsification experiment

After fixing resume and profiling, start at 512 context with B02, R02x4-cycle and B08 at a common width, vocabulary and MLP ratio. Keep data and training schedule fixed across the three arms within each of three paired seeds. Use 10M consumed tokens per arm as an initial budget on a larger corpus, with enough data to avoid repeated epochs. Freeze packing, tokens/update, AdamW, LR schedule, initialization rule, dtype and eval examples. If workload memory requires microbatch changes, preserve examples per update, record changed accumulation and benchmark it. Keep the candidate/control work symmetric if tuning, and use a separate validation split for the tuning budget.

- B02 vs R02x4 tests whether extra applied depth helps at equal stored parameters. B08 vs R02x4 tests the quality cost of tying at equal modeled compute and token budget. Add a conventional run at equal total estimated FLOPs and stored parameters only if asking whether spending FLOPs on extra data beats extra depth. Allocate roughly 3.3 times B02's tokens for that alternate arm, recompute the schedule and label the changed data exposure explicitly.
- Primary quality metric is token-weighted document-held-out NLL. Predeclare an absolute improvement margin of 0.02 nats/token against B02 and a useful gap-closure target of 50% against B08, interpreted only when B08 materially beats B02. Report paired seed differences, uncertainty across seeds, and document-level bootstrap uncertainty separately. Three seeds give a screening result. Add seeds if intervals cross predeclared margins.
- Record loss versus both consumed tokens and estimated/measured compute, pre-clip gradient norms, throughput, peak training memory and downstream sanity checks. Measure batch-one inference on the same GPU/dtype/backend with exact prompt lengths and one standard output budget. Record device-wide peak, allocator peaks, synchronized TTFT and steady-state decode.
- Advance only if depth reliably beats B02, recovers a meaningful fraction of B08's improvement and shows useful measured memory/speed tradeoffs. A well-resolved negligible gain against B02 or under 25% gap closure is evidence to abandon fixed sharing at this scale. Wide intervals or a weak control gap are inconclusive. A resource-constrained sweep of conventional width/depth is needed before claiming a frontier improvement. Qualifying evidence then needs the reference GPU, batch 1, no offload, peak ≤4096 MiB, ≥8 output tok/s and demonstrated usable 8K. The 512 pilot cannot decide the general hypothesis.

## Alternatives with decision tests

- **Grouped-query attention or compact shared KV.** First test identical GQA in both families and verify quality and cache bytes. Sharing K/V between recurrences changes the operator because application inputs differ, so train the altered model and test quality and 8K memory as a separate research arm.
- **State-space or compact recurrent hybrid.** Retain a small number of attention layers and replace other per-token cache streams with bounded state. Prefer this if measured cache dominates and a matched pilot preserves long-range retrieval and document NLL under the same memory and latency budget.
- **Small depth-specific adapters or untied first/last blocks.** If loss plateaus despite healthy early exits and gradients, add a tightly budgeted per-depth modulation. Compare against spending the same storage on increased untied width or additional independent blocks.
- **Native low-bit weights.** Train with the intended representation and demonstrate actual packed inference plus compatible kernels. This is most useful when weights are a material fraction of measured peak; compare against a cache-efficient control at equal quality and memory.
- **Adaptive depth.** Pursue after late-iteration gains are established and vary by example. Measure wall-clock decode and tail latency at fixed quality. Design KV semantics explicitly for tokens that halt at different depths.

Run the small controlled comparison after the integrity and measurement blockers are addressed. If sharing improves 512-token quality but misses the equal-memory 8K frontier because of KV growth, test a cache-reduction variant before adding more depth. If it loses at equal compute and offers no useful memory-speed point, retire the fixed-loop variant at the tested scale.
