DOMOVOI LABS — INDEPENDENT ARCHITECTURE AUDIT
23 November 2026 | domovoi_recurrent_v1

1. Executive summary and scope
The shared-core implementation performs causal depth recurrence as intended on
the tested CPU paths. Weight identity, causal prefix independence, valid
incremental decoding and tied gradients passed independent checks. The main
blockers are research integrity on resume and measurement validity. At 8K,
22.75% is a theoretical reduction in logical BF16 weights plus logical cache
against an equally deep control. This checkout has no evidence of an 8K
capability or peak-memory gain. Prioritize a narrow pilot after the fixes below.

5. Findings
DML-A01 | HIGH | Confirmed | High confidence
  domovoi/training/trainer.py:76–127; training/checkpoint.py:124–162;
  scripts/train.py:58–111.
  Same-shape recurrence changes pass checkpoint load. The trainer builds
  from CLI config, validates tensor keys/shapes during load and warns about
  changed steps. It never compares the saved architecture schedule to the
  active one. Reproduce with the checkpoint probe in the log: a depth-2 cycle
  save loaded into depth-3 sequence and changed logits by 0.177509. Checkpoint
  inference reconstructs the saved config and passed an exact round trip.
  A missing resume checkpoint also falls back to step zero. An explicit
  experiment directory bypasses allocation, even for a fresh run. Mixed
  histories could pass as a single trajectory or write into DML-0001.
  Require explicit fresh/resume/fork modes, fail closed before any writes,
  validate resolved config and data hashes, and enforce a single writer.
  Record deviations and give forks fresh run IDs.

DML-A02 | MEDIUM | Confirmed | High confidence
  domovoi/models/baseline_transformer.py:194–220 and :78–99.
  A heterogeneous cache uses the first slot for positions and permits
  different histories in other slots. Shortening slot 1 from 5 to 2
  produced a 0.00435843 max logit error with no exception; an empty cache
  caused IndexError before length validation. Normal generate uses its own
  consistent cache. Validate slot count first, then batch/head/dim/length,
  device and dtype. Bind reusable cache objects to schedule and model
  identity if callers can switch either. Same-shaped slots currently have
  no provenance, so experimental cache reuse needs additional checks.

DML-A03 | HIGH | Confirmed defects and measured CPU allocation | High confidence
  domovoi/models/baseline_transformer.py:73–80 and :223–225;
  domovoi/inference/generate.py:28–37, :106–120 and :133–170;
  domovoi/profiling/profiler.py:71–99 and :105–132.
  Prefill K/V are views of fused QKV and retain Q storage. The independent
  probe counted 43,200 underlying bytes for 28,800 logical K/V bytes. Decode
  concatenates every K/V and keeps the old full cache live during forward.
  The profiler has a reportable dtype mismatch: analytical weights and KV
  assume 2 bytes while checkpoint construction and loading produce FP32 by
  default. Timing samples perf_counter after launching CUDA prefill, before
  sampling synchronizes, so GPU TTFT is not a completed first-token latency.
  Each generate resets peaks and the aggregate reads only the last run.
  Context strings may undershoot targets (a word tokenizer produced 9 for
  both 16 and 32); exact-full prompts provide zero decode tokens. These are
  disqualifying for a memory/speed frontier. Use exact input IDs, reserve
  decode headroom, report dtype/backend and actual lengths, synchronize or
  use CUDA events, take peaks across repeats, measure allocated/reserved and
  device-wide usage, and account for all transient logits/cache allocations.
  Test static cache and final-position-only prefill logits separately.

6–8. Mathematical architecture, cache and memory
Let n be stored blocks, r repeats, A=n*r, d width, f MLP width, V vocabulary,
C positional capacity, T actual length and B batch size. x0=E[token]+P[pos].
Each step applies x'=x+Attention(LN1(x)), then x_next=x'+MLP(LN2(x')).
Cycle repeats the stack, sequence repeats each block before advancing.
This is fixed-depth recurrent computation over residual states, implemented
as repeated ordinary blocks. Different activations reach the same weights.
Training autograd retains per-application states. Across tokens the only
carried state is KV. Sharing parameters does not justify sharing these states.
Pre-LN gives an identity residual gradient path; it does not bound products
of correlated Jacobians. Sharing can align gradient contributions or cause
cancellation. Projection initialization scales by 1/sqrt(2A), which need
not stabilize repeated correlated updates. Track pre/post-clip gradients,
residual norm, update-to-weight ratio, cosine similarity between iterations
and early-exit loss. Final-head early-exit metrics are diagnostics since that
head was optimized for final depth. Saturation and capacity limits remain
hypotheses.

Cache slot j must store K/V from the state entering application j, even when
two slots use the same block. Causality follows by induction through depth:
position p uses only prefix states through p; positionwise norms and MLPs
preserve the property. Fresh prefill uses causal SDPA, singleton decode uses
all available keys, and chunk query i allows keys <= prefix+i. Position IDs
start at prefix length. Independent chunkings include full length, length 1,
mixed chunks and final context boundary. Existing tests cover greedy boundary
behavior including empty/overlength prompts in the overall suite. Valid
caching passed. The malformed-cache counterexample is DML-A02.

Block parameters P=4d²+2df+9d+f, including two affine norms and five d plus
f linear biases. Unique U=(V+C)d+2d+nP+(untied?Vd:0); applied count replaces
nP by AP. For an attended length L the per-query forward matmul estimate
is A(8d²+4df+4dL)+2Vd. Prefill multiplies the projection/head term by BT
and uses B*T*(T+1)/2 valid attention pairs per layer. Dense math kernels
may compute a full T×T rectangle; softmax, normalization, GELU, memory
traffic and backend effects are omitted. Decode has L≈T and concatenation
adds O(BATd) copying per step. Backward roughly adds 2x forward matmuls,
ignoring optimizer, clipping and recomputation. CPU validation checked
the formulas, without hardware FLOP counters.

Logical KV is 2*B*A*T*d*bytes_per_KV. Training saved activations include
O(BAT(d+f)) and possibly O(BAhT²) attention storage for h heads with a
materializing backend; fused SDPA can avoid the latter. Logits scale BTV.
Training memory adds weights, gradients and AdamW moments (roughly 16 bytes
per parameter for FP32 weights, gradients and both moments) plus AMP casts,
allocator workspaces and temporary buffers. Activation checkpointing trades
extra compute for saved activations. Inference peak includes weights, KV,
logits, per-block workspace, transient old/new cache, sampling and allocator
and process overhead. Reducing physical weights can help bandwidth or
resident storage, but recurrence still executes each application.

8K example, tied embeddings, d=640, f=1728, V=4096, A=16, B=1,
learned position table resized to 8192 and all storage BF16:
  B16    69,589,248 params 132.73096 MiB weights 320 MiB KV 452.73096 total
  R02x8  15,581,056 params  29.71851 MiB weights 320 MiB KV 349.71851 total
  Difference 103.01245 MiB, 22.75% of B16.
Fused prefill backing allocations alone can add another 160 MiB to either
cache. With that shared overhead the fraction falls to about 16.81% before
logits/workspace. 8K×4096 logits add up to 64 MiB in BF16 or 128 MiB in
FP32. Standard checkpoint inference uses FP32 and can approximately double
logical tensor bytes relative to this example. Equal overhead dilutes a
percentage and can preserve the absolute weight delta. Different peak
allocation behavior or throughput can erase practical advantage. Only
same-backend measured peak and speed can decide.

9–13. Experimental fairness, reproducibility, fixes and research value
See docs/CODEX_ARCHITECTURE_REVIEW.md for the pilot, dataset and positional
migration. At context 512, B02 and R02x4 store the same count but estimated
training FLOPs/token differ by about 3.3x, including the shared output head.
B08 and R02x4 match approximate matmul work and differ in optimizer work,
weight capacity and potentially bandwidth. Use AdamW matrix-only decay
and cosine/warmup consistently (training/optim.py:16–47). Parameter-count
matching does not match gradient statistics. Same integer seed gives an
independent data generator but is not matched initialization across shapes,
because module allocation consumes RNG before explicit initialization.
At equal effective depth, residual projection scaling matches; at equal
stored count and different A it does not. Document initialization and add
a matched initialization sensitivity run if it changes the conclusion.

Preserve DML-0001 as history. Use clean versioned source plus dirty-diff
hash, environment/package lock, CUDA runtime/driver/backend and dtype,
tokenizer/packed split hashes and RNG provenance for future runs. Present
exact same-environment resume separately from cross-platform numerical
equivalence. Existing CPU resume tests cover ordinary and injected
forward/evaluation interruption, but not interruption during a partially
applied optimizer update. Review trainer.py:251–272, :312–323 for that risk:
RNG rollback alone cannot undo partial parameter mutations. Use a last
committed full checkpoint as the recovery authority and reconcile metric
rows after restart. No verified dependency vulnerability is reported.

The baseline subclass hook is small and reuses masking logic productively.
Separate the immutable baseline control from experimental entrypoints at
the revision or test-fixture level. Shared tested leaf modules are reasonable.
A duplicated attention implementation would add drift. A new execution path
is justified when cache semantics, adaptive schedules or positions diverge.

14. Final decision
APPROVE AFTER FIXES
The CPU evidence supports the core design. Resume integrity, production
measurement fidelity and controlled comparisons must be fixed before the
first research run. An affirmative pilot would justify a longer-context
follow-up, with claims restricted to the tested scale and hardware.
